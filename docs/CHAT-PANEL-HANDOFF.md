# 铸文：AI 聊天面板重构交接（本轮）

核对日期：2026-09-17。本文只记录**本轮实际改动与实测结果**，不重复历史交接文档内容。

## 一、选型结论：没有采用 assistant-ui（记录不兼容点）

评估对象与结果：

| 方案 | 版本/许可 | 结论 |
|---|---|---|
| `@assistant-ui/react` | 0.15.20 · MIT | **未采用**（理由见下） |
| `prompt-kit` | 组件源码复制式（shadcn 风格） | 仅参考组织方式，未引入依赖 |
| `use-stick-to-bottom` | **1.1.6 · MIT** | **已采用**，仅用于流式滚动 |

未采用 assistant-ui 的具体原因（实测依赖树）：

1. 其依赖包含 **`assistant-cloud`**（云服务包）。本项目硬约束是本地优先、不引入云端会话存储与遥测，引入该包与该约束直接冲突。
2. 依赖面较大：`radix-ui`、`zustand`、`zod`、`assistant-stream`、`@assistant-ui/{core,store,tap}`、`safe-content-frame`、`react-textarea-autosize` 等 11 个直接依赖；而本项目前端运行时依赖目前全部收敛在 devDependencies 且极少。
3. 运行时模型与本项目状态所有权冲突：主进程持有唯一会话真相（`aiSession` + 数据库 + 草稿通道）并广播快照，流式期间的 assistant 消息**没有稳定 ID**（完成时才写库并分配 id）。assistant-ui 的 runtime 要求自己持有消息数组与稳定 id，需要额外维护一套影子状态，等于制造第二份真相。
4. 结论：**保留现有状态层 + 精选单点组件**，符合提示词允许的替代路径。

`use-stick-to-bottom` 置于 `devDependencies`（与 react/marked 等一致，构建期打包进 dist）。未新增其他依赖。

技法卡新增“系统博弈成长连载”组合（主体能动、规则验证、信息差与连载兑现）；两张新增内置卡补齐英文名称/说明。自定义卡编辑器显示规则字数及任务适用提示，复制内置卡时名称也按当前语言生成。

## 六、未验证项与已知限制

- **未验证真实 AI 服务商**：冒烟不请求 LongCat/公网；`npm run test:ui` 通过仅绑定 `127.0.0.1` 的 OpenAI-compatible SSE Echo，走真实 `ai:send` IPC、请求组装、SSE 分块解析、流式消息更新和 SQLite 持久化。该测试验证客户端传输链路，不代表 LongCat 鉴权、网络、限流或长回复压测通过。
- **未实现隐式排队发送**（按提示词要求本轮不做）：生成中允许继续编辑草稿，但发送按钮在生成中不触发新请求。
- 消息重试：已支持从成功回复打开菜单，选择保留原回复并在新分支自动重新生成，或回到原提问编辑后手动发送；生成中的版本切换仍未实现。
- 长会话采用主进程/数据库分页：打开会话时主进程只载入最近 80 条（若切在问答中间，会多带上一条用户提问），点击“加载更早消息”每次从 SQLite 读取一页，并补偿滚动高度以保持视口锚点；后续新消息滑出主进程窗口时，渲染层保留已载入消息。这样限制了活动会话在主进程中的消息内存与初始 IPC；发送模型请求时仍从数据库组装完整历史，尚未减少请求上下文长度。打开上下文面板时按需读取完整会话统计；统计未返回前，分类明确标为“最近已载入消息”。历史会话列表本身也支持分页。
- **未做虚拟化**：长对话滚动性能未测；未测前不引入。
- **截图**为无连接状态的空会话/引用选择器/历史抽屉/更多菜单/已填输入；**未覆盖**深色主题、减少动效、展开视图的截图。
- 未提交、未打包、未覆盖 `release/Zhuwen-Setup-0.4.8.exe`（该安装包不含本轮改动）。

## 后续补充（2026-10-26）

- 长会话打开时主进程只保留最近 80 条消息；SQLite 负责更早消息分页，渲染层保留已加载历史。构造模型请求仍从数据库取会话历史。
- 固定托管连接的 30 万字符上下文上限由界面预览与主进程请求边界共同核验。超限时按完整用户轮次从最早记录开始裁剪，保留最新提问；本地历史不删除，请求预览会显示系统提示，发送时告知作者省略条数。若仅当前输入/固定规则本身超限，仍会在本地阻断。
