## 第一阶段：修复已识别的正确性问题

### A. 外观偏好完整性（优先）

检查 App.tsx 首次引导中 preferences:set 的 appearance 值。目前只提交 { theme: t }，主进程整项替换，可能清除背景、字体、语言、面板宽度等字段。

要求：实现统一的偏好更新入口，更新部分字段保留其他字段；避免用过期快照覆盖用户刚修改的值。首页、引导、工作台和浮窗使用一致状态。保存失败显示错误并回滚或明确保留未保存状态。

验收：预先设置背景、字体、语言、透明度，再通过引导和首页切换主题，重启后其余字段仍一致；模拟保存失败不能显示已保存。

### B. 统计日期与口径（优先）

目前 writing:stats 使用 GROUP BY date + LIMIT N，得到最近 N 个有记录日期，不是近 N 个日历日。stats-center 又使用同一结果计算本周、本月和连续天数，切换 7 天范围可能导致月汇总不完整。

要求：按本地日历明确计算起止日期，查询限定时间范围；趋势补齐无记录日期为零。周/月汇总与趋势范围独立，不随 7/30/90 天切换发生错误变化。连续记录按明确口径统计，历史不足时不得伪装完整统计。负净增日如何算活跃、净增零的修改日能否识别，需在实现记录中说明。

负数图表使用零基线与向下柱，不把负数统一压成 2px。全部作品/单部作品的统计范围必须标明。不得让同一个“每日目标”在首页表示全部作品、工作台却无提示地表示单本作品。

验收：覆盖跨月、跨年、周一边界、无记录日、负净增、历史稀疏记录、全部与单本、7/30/90 天切换；本周本月数值不受趋势筛选影响。

### C. 数字动画生命周期

daily-goal.tsx 当前在状态更新函数内启动 requestAnimationFrame，未清理；严格模式、快速连续更新和卸载可能留下重叠动画。CSS 减少动态效果不能停止这段 JavaScript。

要求：副作用只在 effect 中启动；更新和卸载取消旧帧，从当前显示值平滑追踪最新真实目标，最终准确收敛。整数显示，使用等宽数字。系统减少动态效果或应用关闭动画时直接显示真实值。

达标提示每个本地日期及明确目标作用域最多触发一次；删除后再次达到不反复庆祝；初次打开已达标页面不重复庆祝。跨午夜应主动刷新日期和今日统计，不依赖再次输入。

验收：连续快速增减、组件卸载重挂、严格模式、减少动态效果、跨日、超过目标、负数、目标为零；最后显示值与真实统计一致。

### D. 修复界面验收入口

electron/main.ts 的界面冒烟仍使用 .shelf-head、.stats 等旧结构，当前首页为 CreativeHome、统计为 stats-center，首次引导也需处理。

要求：使用稳定测试标识定位界面；覆盖首次进入引导和已有偏好两条路径。断言真实创建、输入后落库、统计与主题切换，不仅断言元素存在。不删除旧关键验收项以获得通过。

## 第二阶段：统一视觉系统

整理 styles.css、themes.css、design-tokens.css、cursor-layout.css 的重复规则与覆盖关系。保留兼容类名，逐步统一颜色、材质、圆角、间距、字体与动效参数。不能只在末尾持续叠加覆盖规则。

- 三个主题都完整覆盖首页、工作台、浮窗、设置、弹窗、表单、菜单、统计和错误状态。
- 顶栏侧栏使用轻玻璃；正文区域保持高不透明度与稳定文字对比；上传背景不能干扰正文阅读。

- 减少透明效果时改为实色；减少动态效果时禁用非必要动画；两种设置独立。
- 统一 SVG 图标的尺寸、线宽与点击区域，替换杂乱字符按钮；重要按钮保留文本或可访问名称。

验收：至少检查 780×560、1280×800、1920×1080 的布局及 Windows 125%/150% 缩放可用性；测试三主题、背景开关、减少透明与减少动态效果。若设备无法测试某项，明确标为未验证。
