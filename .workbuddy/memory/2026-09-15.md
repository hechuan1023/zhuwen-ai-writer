### 换行符（重要，易埋雷）

- 源码实际**全为 LF**（`b.count(b'\x0d') == 0` 验证）。
  ⚠️ `grep -c $'\r$'` 在本机 MSYS 环境会**假阳性**报「全行 CRLF」，判断换行符一律用 `od -c` 或 Python 字节统计。
- Git for Windows 在**系统级** config 写入 `core.autocrlf=true`（`git config --global` 查不到）。
  后果：检出时工作区被整体改写成 CRLF → 全文件级伪 diff。
- 修法：新增 `.gitattributes`（`* text=auto eol=lf` + 二进制标记），并设仓库级 `core.autocrlf=false`。
- **已用真实 clone 实测**：克隆继承系统 `true`，但工作区 **0 个含 CR 文件**，保护生效。

### 踩坑

- **MSYS 路径陷阱**：原生 Windows 版 git 把 `/tmp/x` 解析成 `E:\tmp\x`，而 bash 的 `cd /tmp/x` 落在 MSYS 临时目录 → `&&` 链断后**后续命令在项目原目录继续跑**，克隆验证实际验的是原项目，还报出一堆假「异常」。**凡传给 git 的路径一律用 Windows 风格绝对路径（`E:/...`）**，关键结论要打印 `pwd` 自证。
